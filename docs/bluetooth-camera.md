# 蓝牙与相机：诊断进展及失败记录

记录日期：2026-10-21。适用硬件、内核版本见[状态表](status.md)。**本页保留早期未成功的诊断过程；蓝牙后续已完成扫描、配对、连接和重启后再次连接，见[最终修复](bluetooth.md)。相机仍不可用。** 用户确认三项硬件在此前 Android 中均能正常工作。

## 蓝牙：串口编号只是第一个阻塞

当前 UART `4a8c000.serial` 报 `Invalid line -19`，设备树缺少它需要的 serial/hsuart 别名。仅接管这个未绑定 UART 的临时模块，补齐 GPIO8～11 的 qup3 pinctrl，以及原厂 L17/L23 供电引用后，能建立 tty/serdev/hci0，但 QCA 版本查询仍超时，不能扫描或配对。

已核对的硬件事实：

- 控制器为 QUP v3，UART 固件主、次序列器均为 `0x204`。
- 115200 baud 的实测时钟为 7372800Hz、分频4、16倍采样，与原厂 `CONFIG_SERIAL_MSM_GENI_HALF_SAMPLING=y` 一致。
- 原厂 BT 核心电源要求 L17 为 1304000µV，临时投票实测达到；撤下后恢复此前电压。
- GPIO87 是芯片 SW_CTRL **状态输入**，不能当成普通使能输出随意拉动。只读观察到它随关/开脉冲变化。
- UART 内部回环发送 `01 00 fc 01 19`，收到相同5字节。它验证 UART 内部收发，不证明外部引脚或蓝牙芯片通信正常。

### 必须纠正的测试错误

临时模块为避免注册调试控制台，取消了 `CONFIG_SERIAL_QCOM_GENI_CONSOLE`。但上游的 FIFO 接收助手也受该配置控制，结果误编译为空函数。最初 FIFO 数据未接收的阴性结果全部作废，不能归咎于芯片或用来排除某项修正。

定位依据是内部回环时 RX FIFO 已有5字节，但接收计数仍为0。保留完整接收函数、继续禁止注册控制台后，回环才通过。早期 DMA 测试不走这个函数，结论范围应独立区分。

修正后重新测试 QCA 初始化时序、原始串口版本查询和共享无线电源重启，仍未获得有效 HCI 回复。检查接收错误丢弃路径时，只见 `00` 字节，没有证据支持直接取消所有错误检查。原厂电源序列、串口重新打开、硬件握手和外部通信仍需继续定位。

共享电源试验中，Wi-Fi 临时解绑后 L16/L17/L23 的 use/enable 计数降为0；L9仍由其他设备保持，因此不能称为整个芯片完全断电。Wi-Fi 重新绑定会异步创建 wlan0，恢复脚本需等待接口出现，不能过早把“接口尚未创建”当成恢复失败。最后已重新连接 Wi-Fi。

早期阶段恢复了原 `hci_uart`、撤下所有诊断模块，未留蓝牙开机配置。后续的根因定位、可用外部UART与开机服务见[新记录](bluetooth.md)。另纠正旧判断：本内核虽然没有启用 `CONFIG_BT_LE`，匹配源码仍始终编译SMP，该选项主要控制ISO；不能据名字断言所有BLE功能不可用，也不能据扫描成功宣称所有BLE外设或LE Audio可用。

同芯片参考是 [Damir00109/Redmi10c 的固定提交](https://github.com/Damir00109/Redmi10c/tree/ebe10a8471e5a43f6bdfd08a30ebe4493a28d08e)。本机仅把其FIFO/QCA时序改动作为对照；后来修复的决定性证据是本机GPIO11的实际mux与IRQ调用链。不能照搬另一台设备的GPIO保留表、固件或板级资源。

## 相机：后摄身份与处理单元已读出

当前启动内核没有启用 `CONFIG_MEDIA_SUPPORT`，也没有可用 video/media 相机节点。安装相机应用不能补上缺失的内核驱动。

| 检查项 | 本机结果 |
| --- | --- |
| CCI 控制总线 | 临时建立两个 master；硬件版本 `0x10020009`，时钟37.5MHz |
| 后摄 | 原厂供电顺序、19.2MHz MCLK；7位地址 `0x10`、寄存器 `0x0000` 读到 `0x487b`，确认为 Samsung S5K4H7 |
| 后摄 GC08A3 候选 | 地址 `0x31` 返回 NACK；不能因此改写实际读出的 Samsung 型号 |
| 前摄 | 原厂 master1 上两个候选均超时；SDA/SCL 仍为低电平，型号尚未确认 |
| 前摄路由对照 | 保持后摄复位低，在 master0 上检查前摄候选均 NACK；不能冒用后摄 ID |
| CSID0 | 物理 `0x5c6e000`，版本 `0x10000003` |
| TFE0 | 同一资源偏移 `0x1000`，版本 `0x10020000` |
| TFE BUS | 偏移 `0x1a00`，版本 `0x20010000` |

身份识别只写 I²C 寄存器地址，再重复起始读取；未初始化传感器流、未改 EEPROM、未启动图像 DMA、没有拍照。供电/GPIO/时钟均在测试后恢复。

CCI 控制器实际使用 `qcom,gcc-sm6225` 的时钟编号；最早误用 sm6115 编号曾引起时钟超时，已修正。原厂和主线的 pinctrl 设备名称也不同，不能把 Android 的 `400000` 路径名称直接用于当前 `500000.pinctrl`。

### TFE340 对照中的误判

原厂 TFE530 头文件的 `reg_dump_data` 表与实际运行用的 `common_reg`/`bus_client_reg` 表并不一致。之前根据 dump 表推断 TFE340 布局不兼容，判断过早。

应使用运行表：TFE版本、BUS版本、client0配置偏移分别为 `0x1000/0x1a00/0x1c00`；主线 vfe340 为 `0/0xa00/0xc00`。VFE资源起点加 `0x1000` 后，这些关键寄存器对齐。CSID 的 RDI0 配置也对应 `0x300`。**这只是兼容线索，还不是完整 IRQ、PHY、复位、时钟、IOMMU 和 DMA 路径验证。**

参考[上游 TFE340 提交](https://github.com/torvalds/linux/commit/acf8d084699e1b5ed7ca0fbc01a6e3f63d10a0df)、[CSID340 提交](https://github.com/torvalds/linux/commit/f0fc808a466a544420807df2c7a42f7bc322d245)及作者的 [Fairphone 6 TFE530/665 逆向说明](https://nondescriptpointer.com/articles/fairphone-6-wide-camera-linux/)。另一平台的成功不能替代本机验证。

## 媒体框架通过，CAMSS 图注册失败

在独立构建目录增加媒体配置，未改变已验证触控模块的原构建配置。核对各模块全部外部导出后，下列匹配6.14源码的模块在本机成功加载并完整卸载：

`mc`、`videodev`、`v4l2_async`、`v4l2_fwnode`、`videobuf2_common`、`videobuf2_memops`、`videobuf2_v4l2`、`videobuf2_dma_sg`。

随后回移 TFE340/CSID340 做禁止打开视频、禁止流传输、IRQ不自动启用的图注册试验，**该试验失败，不能安装或重复使用**。错误在临时资源模块，而不是上游 TFE 驱动已经被证明有缺陷：

```c
/* 错误示意，禁止运行：该内核不支持这里的 NULL alias_dev。 */
regulator_register_supply_alias(dev, id, NULL, "l4");
```

该内核实现先把映射加入链表，再在日志中调用 `dev_name(alias_dev)`，空参数导致内核 Oops。只看函数声明和导出存在，无法证明参数语义或运行安全，必须核对匹配版本的实现。异常后模块卡在 Loading，正常卸载失败；未尝试强制卸载。

当时桌面、触控服务、Wi-Fi、串口仍运行。确认没有实验开机配置后，普通重启清除动态节点、供电别名及失败模块。重启后核对 boot ID 已变化，所有实验模块/节点消失，原触控模块哈希一致，桌面进程及服务正常，Wi-Fi connected，无失败服务和本次启动的内核 Oops/GPU fault。没有刷 boot、dtbo 或分区表。

不发布这组失败二进制和可直接运行的试验包；私有构建、打包及试用入口均已停用。当前相机功能依然不可用。

## 继续开发前需要完成什么

1. 蓝牙：早期外部通信阻塞现已排除，固件/本机地址与连接已验证；深度唤醒、自动重连、音频播放及更多外设仍需独立测试，见[边界](bluetooth.md)。
2. 后摄：完成本机19.2MHz模式的 S5K4H7 V4L2 驱动、板级供电和端点描述。
3. 图像路径：逐项验证 CSIPHY1.2.1、CSID/TFE的复位和IRQ、时钟/带宽、SMMU映射，再开始最小帧采集。
4. 前摄：先解决控制线低电平并读出真实型号，再谈图像流。
5. 用户态：原始 Bayer 帧、软件 ISP、色彩/曝光及相机应用是后续独立验证阶段。

本页是排障证据和失败复盘，相机支持仍未完成；蓝牙当前状态以[后续修复记录](bluetooth.md)为准。更多固定来源和下载校验见[来源清单](../SOURCES.md)。
