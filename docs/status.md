## 验证边界

- 安装、文件系统检查和 sparse 往返比较先在电脑完成，随后才写设备。
- 实际验证了桌面、单指点击/滑动、返回应用列表、Wi-Fi 和正常重启。
- 先后经历 GNOME GPU 故障、纯软件 Phosh，再启用保守的 GPU 合成。
- GPU 限制 devfreq 目标为 320MHz；`cur_freq` 曾采到 320/465/320MHz，不能宣称始终硬锁 320MHz。
- 多点槽位在代码中实现，但本轮使用者主要验证单指；不保证十指、掌触、压力或手写笔。
- 深度休眠仍禁用；音频、相机、蓝牙、传感器、硬件视频解码、Vulkan 和可靠充电/续航没有完整测试。
- 图形应用仍使用软件绘图，GPU 合成成功不等于所有应用已硬件加速。
- 应用启动补丁通过重新建立桌面会话实测；未为该用户态补丁再次刷写或重启整机。
- 后续发现普通熄屏也会影响TDDI触控，禁用整机深度休眠并不足以覆盖它。已新增保留input设备的暂停/恢复控制和亮屏恢复服务，经过三轮软件电源循环及用户滑动复核；没有为这次修复再次重启整机，长期休眠仍不宣称可用。
- 蓝牙复查发现UART报`Invalid line -19`，live DT缺少该UART的serial/hsuart别名；载入现有蓝牙模块后BlueZ可运行，仍没有HCI控制器，且`CONFIG_BT_LE`未启用。相机方面`CONFIG_MEDIA_SUPPORT`未启用且没有video/media设备节点。两项目前未修好。
